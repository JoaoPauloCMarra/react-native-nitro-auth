# Nitro Auth example app

Expo (CNG) app that exercises `react-native-nitro-auth` on iOS, Android, and web.
`android/` and `ios/` are generated by `bun run example:prebuild` and are not committed.

## Configure provider IDs

Copy `.env.example` to `.env` and fill in the IDs you need. The config plugin
reads them during prebuild. Run prebuild again after changing any value.

## Run with a different iOS bundle ID

The example uses `com.auth.example`. A free Apple team cannot sign that ID, so set
your own before prebuild:

```bash
NITRO_AUTH_IOS_BUNDLE_ID=com.yourname.nitro.auth.example bun run example:prebuild:clean
```

You can also put the value in `.env`. A bundle ID change also changes provider
registrations. Update both providers before you test sign-in.

### Google

1. Open Google Cloud Console, then APIs & Services, then Credentials.
2. Create an OAuth client ID of type **iOS** and enter the override bundle ID.
3. Set `GOOGLE_IOS_CLIENT_ID` to the new client ID. Leave `GOOGLE_IOS_URL_SCHEME` empty
   or set it to `com.googleusercontent.apps.<client-id-prefix>`. The plugin derives the
   URL scheme from the client ID when you omit it.
4. Run prebuild again so `GIDClientID` and the URL scheme reach `Info.plist`.

Android and web keep using `GOOGLE_WEB_CLIENT_ID`. The Android package stays
`com.auth.example`.

### Microsoft

1. Open the Microsoft Entra app registration, then Authentication.
2. Under **Mobile and desktop applications**, add the redirect URI
   `msauth.<override bundle ID>://auth`, for example
   `msauth.com.yourname.nitro.auth.example://auth`.
3. Keep `MICROSOFT_CLIENT_ID` unchanged. The plugin registers the matching
   `msauth.<bundle ID>` URL scheme from the bundle ID.

### Apple

Sign in with Apple needs a paid Apple team. Leave `NITRO_AUTH_APPLE_SIGN_IN` unset on
a free team.

### Replay flows

The agent-device flows in `e2e/` open `com.auth.example`. They do not work with an
overridden iOS bundle ID unless you edit the id in the flow.

## Build speed settings

These settings live in tracked config, so a clean prebuild keeps them. Example
builds never run in CI.

| Setting                                 | Where                                | Override                                                                                             |
| --------------------------------------- | ------------------------------------ | ---------------------------------------------------------------------------------------------------- |
| Gradle build cache, parallel, 6 GB heap | `plugins/with-gradle-build-speed.js` | Edit the plugin, or pass `-Dorg.gradle.caching=false` on the Gradle command line                     |
| Kotlin daemon 3 GB heap                 | `plugins/with-gradle-build-speed.js` | Edit the plugin                                                                                      |
| iOS ccache (`ios.ccacheEnabled`)        | `app.config.js`                      | On when `ccache` is on `PATH`. Set `NITRO_AUTH_IOS_CCACHE=0` before prebuild to turn it off          |
| Android ABIs                            | `app.config.js` (`buildArchs`)       | All four ABIs by default. `NITRO_AUTH_ANDROID_ARCHS=x86_64` before prebuild for emulator-only builds |
| Prebuilt React Native core on iOS       | Expo default                         | `buildReactNativeFromSource` stays unset, so the prebuilt xcframeworks are used                      |

The Gradle configuration cache stays off: `android:assemble` and `android:test` pass
`--no-configuration-cache`. `usePrecompiledModules` stays `false`; see `AGENTS.md`.
Re-run `bun run example:prebuild` after changing any of these values.
